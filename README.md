# tg_autificator

## Как это работает

### Команды:
Кждый день в **08:00** по Москве регламентная задача запускает команду:

```bash
docker compose exec tg-scheduler php artisan telegram:kick-unlinked
```
Команда кикает участников: 
1. без записи в таблице `tg_ids` и в таком случае отправляем сообщение через бота о том, что для вступления в группу необходимо пройти верификацию по коду

2.У сотрудника  `status_employee`: `уволен` (есть еще `активный`) в таком случае отправляем сообщение через бота о том, что сотрудник уволен.

### Последовательность

Группа сервис Telegram не вызывает. Контейнер `tg-poller` крутит `telegram:poll` без остановки: каждый круг это один запрос [getUpdates](https://core.telegram.org/bots/api#getupdates) с `timeout` 25 секунд. Пока событий нет, Telegram держит запрос открытым и в конце отвечает пустым списком, цикл сразу спрашивает снова. Если за эти 25 секунд пришла заявка или личное сообщение, ответ приходит сразу, и сервис его обрабатывает. Номер уже отданного обновления пишется в `telegram.poll.offset`, поэтому следующее `getUpdates` просит только более новые. Заявка приходит как [ChatJoinRequest](https://core.telegram.org/bots/api#chatjoinrequest). Сервис аутентификации в сервис Telegram не обращается. Наоборот ходит только сервис Telegram, с заголовком `X-Internal-Token`.

@startuml
actor Пользователь
participant "Группа ТГ" as Группа_ТГ
participant "Сервис ТГ" as Сервис_ТГ
participant "Сервис аутентификации" as Сервис_аутентификации

== заявка ==
Пользователь -> Группа_ТГ : подаёт заявку
Сервис_ТГ -> Группа_ТГ : спрашивает, есть ли новое\nи ждёт до 25 секунд
... до 25 секунд, если событий нет ...
Группа_ТГ --> Сервис_ТГ : отдаёт заявку сразу\nили пустой ответ через 25 секунд
Сервис_ТГ -> Сервис_аутентификации : этот Telegram нам известен?
Сервис_аутентификации --> Сервис_ТГ : привязан, не привязан или уволен

alt ещё не привязан, заявку не трогаем
  Сервис_ТГ -> Группа_ТГ : берёт постоянную ссылку группы
  Сервис_ТГ -> Пользователь : просит ввести код
else уже привязан
  Сервис_ТГ -> Группа_ТГ : принимает заявку
  Сервис_ТГ -> Пользователь : пишет, что человек добавлен
else уволен
  Сервис_ТГ -> Группа_ТГ : отклоняет заявку
  Сервис_ТГ -> Пользователь : пишет, что сотрудник уволен
end

== код из сниппета ==
Пользователь -> Сервис_аутентификации : открывает страницу и берёт код
Сервис_аутентификации --> Пользователь : показывает 6 цифр
Пользователь -> Сервис_ТГ : пишет эти цифры боту
Сервис_ТГ -> Группа_ТГ : снова спрашивает, есть ли новое\nи ждёт до 25 секунд
... до 25 секунд, если событий нет ...
Группа_ТГ --> Сервис_ТГ : отдаёт сообщение сразу\nили пустой ответ через 25 секунд
Сервис_ТГ -> Сервис_аутентификации : проверяет код

alt код подошёл
  Сервис_аутентификации --> Сервис_ТГ : сотрудник связан с этим Telegram,\nкод на странице меняется
  Сервис_ТГ -> Группа_ТГ : принимает ту же заявку
  Группа_ТГ --> Пользователь : человек уже в группе
  Сервис_ТГ -> Пользователь : пишет, что он добавлен, и даёт ссылку
else такого кода нет
  Сервис_аутентификации --> Сервис_ТГ : код не найден
  Сервис_ТГ -> Пользователь : просит взять код заново
else сотрудник уволен
  Сервис_аутентификации --> Сервис_ТГ : код от уволенного
  Сервис_ТГ -> Группа_ТГ : отклоняет заявку
  Сервис_ТГ -> Пользователь : пишет причину отказа
end

== регламентный кик, 08:00 ==
Сервис_ТГ -> Сервис_аутентификации : просит список всех привязанных Telegram
Сервис_аутентификации --> Сервис_ТГ : отдаёт список
Сервис_ТГ -> Сервис_аутентификации : снова спрашивает, кто привязан, а кто уволен
Сервис_аутентификации --> Сервис_ТГ : привязан, не привязан или уволен
Сервис_ТГ -> Группа_ТГ : исключает непривязанных и уволенных
@enduml

Вызовы со схемы:

| Что на схеме | Вызов |
| --- | --- |
| Спрашивает, есть ли новое, и ждёт до 25 секунд | [getUpdates](https://core.telegram.org/bots/api#getupdates), `timeout` 25 секунд. В запросе только `message`, `chat_join_request`, `chat_member`, `my_chat_member` |
| Отдаёт заявку | [Update](https://core.telegram.org/bots/api#update) с [ChatJoinRequest](https://core.telegram.org/bots/api#chatjoinrequest) |
| Отдаёт сообщение с кодом | тот же `getUpdates`, в обновлении обычное `message` |
| Этот Telegram нам известен? / кто привязан, а кто уволен | `POST /api/internal/tg-ids/check`, тело `{ "id_tg": ["…"] }`. Ответ: `linked`, `unlinked`, `fired` |
| Берёт постоянную ссылку группы | [getChat](https://core.telegram.org/bots/api#getchat), поле `invite_link` |
| Просит ввести код / пишет человеку | [sendMessage](https://core.telegram.org/bots/api#sendmessage) |
| Принимает заявку | [approveChatJoinRequest](https://core.telegram.org/bots/api#approvechatjoinrequest) |
| Отклоняет заявку | [declineChatJoinRequest](https://core.telegram.org/bots/api#declinechatjoinrequest) |
| Открывает страницу и берёт код | `GET /api/widget/code` |
| Проверяет код | `POST /api/internal/codes/verify`, тело `{ "code", "id_tg" }`. `200` — `{ "id_ad", "id_tg" }`, `404` — кода нет, `403` — сотрудник уволен |
| Просит список всех привязанных Telegram | `GET /api/internal/tg-ids` |
| Исключает непривязанных и уволенных | [banChatMember](https://core.telegram.org/bots/api#banchatmember) |

`X-Internal-Token` должен совпадать с `INTERNAL_API_TOKEN` сервиса аутентификации. Вызовов из сервиса аутентификации в сервис Telegram нет.

1. Пользователь жмёт «Подать заявку» по ссылке закрытой группы. Как устроены заявки: [Join requests](https://core.telegram.org/bots/features#join-requests).
2. Сервис Telegram получает [Update](https://core.telegram.org/bots/api#update) с полем `chat_join_request` и сразу вызывает сервис аутентификации: `POST /api/internal/tg-ids/check`, тело `{ "id_tg": ["<telegram id>"] }`. Ответ делит id на `linked`, `unlinked` и `fired` по таблице `tg_ids` и статусу сотрудника.
3. Если человек ещё не привязан, заявку не отклоняют и не одобряют: она остаётся висеть. Бот берёт постоянную ссылку группы методом [getChat](https://core.telegram.org/bots/api#getchat) (поле `invite_link`, ссылку не перевыпускает) и пишет инструкцию методом [sendMessage](https://core.telegram.org/bots/api#sendmessage). Если бот молчит, то же сообщение приходит на `/start`.
4. Если id уже `linked`, бот сразу вызывает [approveChatJoinRequest](https://core.telegram.org/bots/api#approvechatjoinrequest) и пишет «Вы добавлены в группу». Если `fired` — [declineChatJoinRequest](https://core.telegram.org/bots/api#declinechatjoinrequest) и текст про увольнение.
5. Пользователь присылает в личку 6 цифр из сниппета. Это обычное `message`, его бот тоже забирает через `getUpdates`.
6. Сервис Telegram вызывает сервис аутентификации: `POST /api/internal/codes/verify`, тело `{ "code": "123456", "id_tg": "<telegram id>" }`.
   - `200` и `{ "id_ad", "id_tg" }` — Telegram привязан к сотруднику, код в виджете меняется на новый. Бот одобряет ту же висящую заявку через `approveChatJoinRequest`. Человек становится участником и получает «Вы добавлены в группу» и ссылку. Вторую заявку подавать не нужно.
   - `404` — код не найден, заявка остаётся висеть, можно ввести другой код.
   - `403` — сотрудник уволен, заявку отклоняют.
